# v0.11.1 验证记录

在 v0.11.0 首次公开发行后的真实检查中，GitHub 未登录 API 返回限流；公开 Release 附件本身可以下载。v0.11.1 增加签名元数据备用通道，继续尊重 API 退避，不在软件内加入 GitHub 凭据。

- GitHub API 返回 403/429 时，读取同一受信仓库的 `releases/latest/download/update.json` 与签名。API 退避期间不重复请求 API。
- 备用通道仍执行受信公钥的 RSA-3072/SHA-256、架构、版本、来源、文件大小与校验验证；签名损坏时不接受更新，不降级安装。
- 更新、帮助、单实例、任务回调、输入翻译与发布流程测试共 66 项通过；新增限流备用通道、API 退避和篡改拒绝测试。
- 无登录凭据的真实网络检查已使用正式 v0.11.0 签名附件验证成功。v0.11.1 公开后的完整下载和跨版本安装另见下文，不以元数据检查代替实际安装。
- v0.11.0 的原生助手安装、失败回退、隔离配置启动与文档运行时验证继续有效；见 verification-v0.11.0.md。本补丁同时更新 GUI、助手及版本化文档运行时，不改翻译引擎或 API 计费配置。

仍未进行全新 Windows 虚拟机或完整原生依赖重编译验证；程序没有 Authenticode 签名。未调用付费翻译 API。旧版本、用户配置、凭据、缓存、历史与输出保留。

### 实测范围与网络条件

- 公开下载、签名校验、旧版编译助手安装、备份、健康确认及数据保留均已真实验证。旧版 GUI 的完整“下载→安装”点击流程未在本次重新走通；旧版的 API 限流问题由本补丁修复，并有针对性测试。新版 GUI 手动检查已真实验证，不能将其扩大为所有更新交互均经人工实测。
- 本机直连 GitHub API 可用，但附件域名出现超时、重置和短暂解析失败。失败发生在安装前，原程序保持完整。有限重试后，使用电脑上原已运行的代理，通过仅作用于验证进程的 HTTP_PROXY/HTTPS_PROXY 完成下载；更新助手和它启动的新程序继承此环境。
- 未修改系统或用户的全局代理设置，也未将代理写入软件配置。以后从普通入口启动时，是否需要代理仍取决于当时网络；本次不能证明直连下载已经恢复。
- 本机既有 Ctrl+Alt+Y 占用仍如实提示，未擅自更改快捷键。新 Windows 虚拟机、所有 Windows 版本及硬件兼容性仍未实测。

本地原始验证记录保存在 `verification-v0.11.1/`，包括 public-download.json、public-install.json、github-state.json 及更新日志；这些个人环境记录不提交公开仓库。复核脚本为 `scripts/verify_public_update.py`，不会查询凭据或调用翻译 API，且拒绝覆盖已经是当前版本的安装。
