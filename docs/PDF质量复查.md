# PDF 翻译质量复查

日常可以直接对 Codex 说：“用工作流复查这次改动影响的论文，和上次的结果比较。” 大版本前则说：“复查固定清单全部论文。” 不需要提供出错页码或重复整理截图。这是开发验收工具，不是软件界面上的按钮；它能发现缺陷，不能自动修改程序或代替科学审校。

## 两种不同的测试

- 有原文和成品：扫描原文、单语以及双语两侧。它回答“这份交付文件有没有触发规则”，不证明新软件运行过。
- 软件改动后：用 `--rebuild` 对受影响的代表论文另存新输出，再用同一组规则核查。大版本可以离线扫整库；没必要每改一次都付费重译整库。改提示词或换模型时，还应选有代表性的段落验证新译文。

在项目目录运行，使用 `.document-runtime\Scripts\python.exe -X utf8 scripts\pdf_blind_workflow.py`。其后的常用参数：

| 需求 | 参数示例 |
|---|---|
| 复查固定清单 | `"D:\翻译测试资料\测试结果\20261123-十篇全文盲扫-v020\阅读稿复查清单.json"` |
| 只查影响的两篇 | 上一条追加 `--match "04_*" --match "10_*"` |
| 核对其他文件夹已有的成品 | `"原文文件夹" --outputs "结果库文件夹"` |
| 复验候选源码（不发请求） | `"原文文件夹" --rebuild --match "文章名*" --cache "此前任务的缓存.sqlite3"` |
| 只补没有成品的论文 | `"原文文件夹" --outputs "结果库文件夹" --generate --requests 10 --reserve 80000`（仅为示例上限，不建议照此估算全文） |
| 比较上一轮 | 追加 `--previous "上一轮\run.json"`，只比较原文摘要和规则版本均匹配的结果 |

输入目录直接放原文 PDF，输出库可以包含子目录。只给原文目录时优先找其下的配对文件，没有就用源码、零付费预算尝试生成。若找到多个同名结果目录，不会猜测哪份是交付稿；用显式清单指定。格式为 `{"papers":[{"source":"原文.pdf","pair_dir":"已选结果目录","sha256":"原文的SHA-256"}]}`；路径相对于清单，也支持绝对路径。`sha256` 可省略。应保留首次固定的清单，不靠文件修改时间选样。

## 结果怎么用

1. **只交付一个固定入口：[翻译质量测试总表](<D:/翻译测试资料/测试结果/翻译质量测试总表.md>)。** 每篇原文一行，新论文追加，相同原文复测更新当前结论并保留上次结论和记录。打不开本次成品时不以旧 PDF 充数。点击行内链接看 PDF、人工核验项或批次证据；`本轮日志.md` 是证据，不作为新的主入口。
   正式盲扫在整批完成后自动登记。使用其他位置的清单或自定义输出时，用 `--ledger-root "D:\翻译测试资料\测试结果"` 绑定同一总表。自拟短文、反例和单页诊断使用 `--diagnostic`。保留总表目录的 SQLite 索引及原批次证据文件。
2. 只有确实需要判断的项才进入 `待人工核验/请看这里.md`，相同问题归类。检查不设已知错误坐标；回归用例才记录期望命中的错误。
3. 找到共因后，先用坏样本写失败测试，修改源码，再对它和另一篇有同类结构的论文另存复查。比较报告里的“未再报警”不是修复证明，还要核对阅读、复制与邻区。规则或基线变化时先用新规则重查旧成品。

每次默认新建带时间戳的结果目录；`--out` 也必须指向不存在的目录。退出码 `0` 仅表示所有选中文件在当前规则下无报警；`1` 表示被拦下或需复核；输入错误不算通过。普通离线扫描不复制大 PDF。新生成的 `job-*` 包含独立缓存和产物，确认哪些文件还用于复验后再清理，不删除原文、历史或付费缓存。

## 范围

当前验证的是英译简中、左右双语、正文含独立表格，不做图片补译。报告检查页序、续页、两侧复制、空白面板、指定类型的链接/邮箱、编号行、部分表格和矢量双键，以及 PDF 可见的未译标记。保留原因并非都属于漏译。程序不能证明每个科学术语或数字都正确，也不能从低分辨率空白检测推断没有文字重叠。逐句科研含义、复杂图表、部分裁切或分页需要另行验证。生成器只允许当前配置的 HTTPS Responses 接口；不替换供应商，默认零请求，显式允许后仍有全批次请求数和 Token 预留上限，零网络重试。预留不是账单。
